# Estlcam 11 Production Qualification

## Status

Build 008C establishes the first deliberately narrow production-controller qualification for BeBlog CAM.

Reference environment:

- Estlcam 11
- reference build: 11245
- 3-axis milling
- millimetres
- manual tool change

This qualification does not widen BeBlog CAM's machining scope and does not qualify every Estlcam configuration or version.

## Binding boundary

The Estlcam postprocessor is **syntax-only**.

It may translate or remove controller syntax around an already validated NC program, but it must never reconstruct, reinterpret or regenerate machining geometry or machine motion.

The protected production chain remains:

**Operation → Canonical Toolpath → 004T Safe Motion → Preflight → NC Motion Truth → Estlcam syntax translation**

Therefore:

> **Estlcam output must preserve the validated NC motion truth.**

## Automated qualification baseline

008A5 is the automated qualification baseline for the Estlcam profile. It uses the 008A4 combined production job and proves that postprocessing:

- accepts the generated combined job without postprocessor errors
- restricts controller G-codes to G0/G1/G2/G3
- preserves Safe-Z rapid behaviour
- preserves arc-radius consistency
- preserves machine-motion count
- preserves minimum Z
- converts each controller-neutral manual tool-change marker into one bare `M6`
- removes the corresponding `M0`
- emits no `T` parameter with `M6`
- removes modal/program-end commands that are outside the qualified Estlcam subset
- preserves operation order
- terminates with `M5`

These checks are platform-neutral repository contracts and may run in GitHub CI.

## Qualified controller subset

The first production profile deliberately qualifies only the syntax needed by the established reference workflow.

Motion:

- `G0`
- `G1`
- `G2`
- `G3`

Spindle/feed and manual workflow:

- `S...`
- `F...`
- `M3`
- `M5`
- bare `M6`
- established auxiliary M-codes already admitted by the postprocessor contract where generated by the production path

Not qualified for the first production release:

- inch mode
- incremental coordinates
- canned cycles
- coordinate-system changes introduced by the postprocessor
- tool-number parameters on `M6`
- postprocessor-generated geometry or reconstructed motion

## Qualification stages

### 008C1 — Qualification Baseline

Automated repository-level proof that the production postprocessor remains syntax-only and that the existing 008A5 motion/tool-change contract remains the qualification baseline.

This stage does not require Estlcam itself and does not claim real-controller acceptance.

### 008C2 — Reference NC Artifact

Produce a deterministic Estlcam reference NC file from the qualified multi-operation production job. The artifact and its expected properties form the hand-off to manual controller validation.

### 008C3 — Manual Estlcam 11 Acceptance

Run the reference NC through the actual Estlcam 11 build 11245 workflow on Windows and record the result.

Required observations include, at minimum:

- file is accepted by Estlcam
- tool changes appear at the intended operation transitions
- displayed path/order agrees with the BeBlog CAM reference job
- no unexpected controller command changes the intended workflow
- program start/end behaviour is acceptable for the qualified manual-tool-change workflow

This is a manual external-environment gate. It must **not** be moved into GitHub CI merely to make the pipeline look more complete.

### 008C4 — Real-machine Qualification

Where practical and safe, validate the qualified controller output in the real machine workflow, beginning with a controlled dry run before material cutting.

This is a local/manual production acceptance gate and is not GitHub CI.

## QA policy

GitHub CI may verify deterministic, platform-neutral contracts around the Estlcam postprocessor.

Actual Estlcam 11 / Windows behaviour and real-machine behaviour require the corresponding real environment. A synthetic CI substitute does not turn those stages into PASS.

## Release interpretation

008C1 and 008C2 can establish that BeBlog CAM deterministically emits the intended Estlcam reference syntax while preserving motion truth.

Production qualification of the controller workflow itself remains incomplete until 008C3 has been performed in Estlcam 11 build 11245. Real-machine qualification remains a separate 008C4 gate where required by the release decision.
